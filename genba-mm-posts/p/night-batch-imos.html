夜間バッチの同時実行数

Night batches running at once

2026-11-14 · ふつう いもす法累積和

問題

夜間に N 本のバッチ処理が動きます。i 本目のバッチは Sᵢ 分に始まり、Eᵢ 分に終わります。つまり Sᵢ 分から Eᵢ − 1 分までの各分に動いています。

0 分から T − 1 分までの各分について、動いているバッチの本数を考えます。その最大値と、最大になる最初の分を出力してください。

問題 (en)

N batch jobs run at night. Job i starts at minute Sᵢ and ends at minute Eᵢ, so it is running in every minute from Sᵢ to Eᵢ − 1.

For each minute from 0 to T − 1, count the jobs that are running. Print the largest count and the first minute at which it happens.

問題 (my)

ညဘက်တွင် batch အလုပ် N ခု အလုပ်လုပ်သည်။ i ခုမြောက် batch သည် Sᵢ မိနစ်တွင် စပြီး Eᵢ မိနစ်တွင် ပြီးသည်။ ဆိုလိုသည်မှာ Sᵢ မိနစ်မှ Eᵢ − 1 မိနစ်အထိ မိနစ်တိုင်းတွင် အလုပ်လုပ်နေသည်။

0 မိနစ်မှ T − 1 မိနစ်အထိ မိနစ်တစ်ခုချင်းစီတွင် အလုပ်လုပ်နေသော batch အရေအတွက်ကို စဉ်းစားပါ။ ထိုအရေအတွက်၏ အများဆုံးတန်ဖိုးနှင့် ထိုတန်ဖိုး ပထမဆုံး ရောက်သော မိနစ်ကို ထုတ်ပြပါ။

制約

  • 1 ≤ N ≤ 2×10⁵
  • 1 ≤ T ≤ 10⁶
  • 0 ≤ Sᵢ < Eᵢ ≤ T
  • 入力はすべて整数

入力

N T
S_1 E_1
S_2 E_2
⋮
S_N E_N

出力

最大の本数と、その最初の分を空白区切りで 1 行に出力してください。

入力例 1

4 10
1 5
3 7
4 6
8 10

出力例 1

3 4

4 分には 1, 2, 3 本目の 3 本が動いています。1 本目は 5 分に終わるので、5 分には 2 本です。

入力例 2

2 5
0 2
2 5

出力例 2

1 0

ヒント

バッチごとに Sᵢ から Eᵢ − 1 まで 1 ずつ足すと、最悪 N × T 回の計算になります。「ここで 1 本増える」「ここで 1 本減る」という変化だけを記録できないでしょうか。

ヒント (en)

Adding 1 to every minute from Sᵢ to Eᵢ − 1 for each job can take N × T steps. Could you record only the changes: "one more job from here" and "one fewer job from here"?

ヒント (my)

batch တစ်ခုချင်းစီအတွက် Sᵢ မှ Eᵢ − 1 အထိ မိနစ်တိုင်းကို 1 ပေါင်းလျှင် အဆိုးဆုံး N × T ကြိမ် တွက်ရမည်။ "ဤနေရာမှစ၍ တစ်ခု တိုးသည်"၊ "ဤနေရာမှစ၍ တစ်ခု လျော့သည်" ဟူသော ပြောင်းလဲမှုကိုသာ မှတ်ထား၍ မရနိုင်ဘူးလား။

解説

長さ T + 1 の配列 diff を用意し、バッチごとに diff[S] に +1、diff[E] に −1 を書きます。これを左から足していく（累積和をとる）と、各分に動いている本数になります。

書き込みは 1 本につき 2 回、足し合わせは T 回なので、全体で O(N + T) です。区間にまとめて足す処理を、このように「始まりと終わりの変化だけ書いて、最後に累積和をとる」形にする方法をいもす法と呼びます。

「最初の分」を答えるので、最大値を更新するのは本数が今までより大きいときだけにします。

解説 (en)

Make an array diff of length T + 1. For each job, add +1 at diff[S] and −1 at diff[E]. Adding the array up from the left (a prefix sum) gives the number of jobs running in each minute.

That is two writes per job and T additions, O(N + T) in total. Writing only where a range starts and ends and taking the prefix sum at the end is known in Japan as いもす法 (the imos method, a difference array).

Because the question asks for the first minute, update the best only when the count is greater than before.

解説 (my)

အရှည် T + 1 ရှိသော array diff ကို ပြင်ဆင်ပြီး batch တစ်ခုချင်းစီအတွက် diff[S] တွင် +1၊ diff[E] တွင် −1 ကို ရေးပါ။ ထို array ကို ဘယ်မှ ညာသို့ ပေါင်းသွားလျှင် (累積和 prefix sum) မိနစ်တိုင်းတွင် အလုပ်လုပ်နေသော batch အရေအတွက် ရမည်။

batch တစ်ခုလျှင် နှစ်ကြိမ်သာ ရေးပြီး ပေါင်းခြင်းကို T ကြိမ် လုပ်သောကြောင့် စုစုပေါင်း O(N + T) ဖြစ်သည်။ အပိုင်း၏ အစနှင့် အဆုံးတွင်သာ ပြောင်းလဲမှုကို ရေးပြီး နောက်ဆုံးတွင် prefix sum ယူသော ဤနည်းကို いもす法 (imos method, difference array) ဟု ခေါ်သည်။

"ပထမဆုံး မိနစ်" ကို ဖြေရမည် ဖြစ်သောကြောင့် အရေအတွက်သည် ယခင်ထက် ပိုကြီး မှသာ အများဆုံးတန်ဖိုးကို ပြောင်းပါ။

解答 (Java)

import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());
        int n = Integer.parseInt(st.nextToken());
        int t = Integer.parseInt(st.nextToken());

        int[] diff = new int[t + 1];
        for (int i = 0; i < n; i++) {
            st = new StringTokenizer(br.readLine());
            int s = Integer.parseInt(st.nextToken());
            int e = Integer.parseInt(st.nextToken());
            diff[s]++;   // one more job from minute s
            diff[e]--;   // one fewer from minute e
        }

        int running = 0, best = -1, bestMinute = 0;
        for (int m = 0; m < t; m++) {
            running += diff[m];
            if (running > best) {   // strictly greater: keep the first minute
                best = running;
                bestMinute = m;
            }
        }
        System.out.println(best + " " + bestMinute);
    }
}
