ステップアップ7 ステータス履歴の圧縮

Step up 7 · Compressing a status history

2026-11-08 · ふつう ステップアップ文字列

問題

監視ツールが 1 分ごとにサーバーの状態を 1 文字（英大文字）で記録しています。同じ文字が続く部分を「文字 + 続いた回数」にまとめて、記録を短くしてください。

例：AAABCC → A3B1C2

問題 (en)

A monitoring tool records a server's state every minute as one capital letter. Shorten the record by writing each run of the same letter as "letter + how many times in a row".

Example: AAABCC → A3B1C2

問題 (my)

စောင့်ကြည့်ရေး tool တစ်ခုသည် server ၏ အခြေအနေကို တစ်မိနစ်လျှင် English စာလုံးကြီး တစ်လုံးဖြင့် မှတ်တမ်းတင်သည်။ တူညီသော စာလုံး ဆက်တိုက်ပေါ်သည့် အပိုင်းကို "စာလုံး + ဆက်တိုက်ပေါ်သည့် အကြိမ်ရေ" အဖြစ် စုပြီး မှတ်တမ်းကို တိုအောင် လုပ်ပါ။

ဥပမာ: AAABCC → A3B1C2

制約

  • 1 ≤ |S| ≤ 2×10⁵
  • S は英大文字だけからなる

入力

S

出力

まとめた文字列を出力してください。

入力例 1

AAABCC

出力例 1

A3B1C2

入力例 2

Z

出力例 2

Z1

入力例 3

OOOOOOOOOOOOOX

出力例 3

O13X1

ヒント

「今の文字」と「それが何回続いているか」を覚えながら進みます。違う文字が来たら、それまでの分を出力用に足して、数え直します。最後の 1 かたまりを足し忘れないようにしましょう。

ヒント (en)

Walk along the string, remembering the current character and how many times in a row it has appeared. When a different character comes, add the finished run to the output and start counting again. Do not forget the last run.

ヒント (my)

«လက်ရှိ စာလုံး» နှင့် «ဆက်တိုက် ဘယ်နှစ်ကြိမ်» ကို မှတ်ရင်း ရှေ့ဆက်ပါ။ မတူသော စာလုံး ရောက်လာလျှင် ယခင်အစုကို output ထဲ ထည့်ပြီး ပြန်ရေတွက်ပါ။ နောက်ဆုံးအစုကို ထည့်ရန် မမေ့ပါနှင့်။

解説

この方法をランレングス圧縮と呼びます。画像形式や通信でも使われています。

「最後のかたまりを足し忘れる」のが一番多いバグです。ここでは、i を進めながら「次の文字が違う、または文字列の終わり」のときにかたまりを出力することで、最後の分も同じ処理で扱っています。

String に += で足していくと、毎回コピーが作られて O(|S|²) になることがあります。2×10⁵ 文字では遅いので、StringBuilder を使いましょう。

解説 (en)

This is called run-length encoding, and image formats and network protocols use it.

Forgetting the last run is the most common bug. Here a run is written whenever the next character differs or the string ends, so the last run goes through the same code.

Adding to a String with += copies it every time and can become O(|S|²), too slow for 2×10⁵ characters. Use StringBuilder.

解説 (my)

ဤနည်းကို run-length encoding ဟုခေါ်ပြီး ပုံ format များနှင့် ဆက်သွယ်ရေးတွင် အသုံးပြုသည်။

နောက်ဆုံးအစုကို ထည့်ရန် မေ့ခြင်းသည် အဖြစ်အများဆုံး bug ဖြစ်သည်။ ဤနေရာတွင် နောက်စာလုံး မတူလျှင် သို့မဟုတ် string ဆုံးလျှင် အစုကို ရေးသဖြင့် နောက်ဆုံးအစုလည်း တူညီသော code ဖြင့် ပြီးသည်။

String += သည် အကြိမ်တိုင်း ကူးယူသဖြင့် နှေးနိုင်သည်။ StringBuilder ကို သုံးပါ။

စာလုံးတစ်လုံးချင်း String ကို += ဖြင့် ဆက်လျှင် အချိန်ရှုပ်ထွေးမှု O(|S|²) အထိ ဖြစ်နိုင်ပြီး 2×10⁵ စာလုံးအတွက် နှေးလွန်းသည်။

解答 (Java)

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String s = sc.next();
        StringBuilder sb = new StringBuilder();
        int run = 0;
        for (int i = 0; i < s.length(); i++) {
            run++;
            boolean last = i == s.length() - 1;
            if (last || s.charAt(i + 1) != s.charAt(i)) {
                sb.append(s.charAt(i)).append(run);
                run = 0;
            }
        }
        System.out.println(sb);
    }
}
