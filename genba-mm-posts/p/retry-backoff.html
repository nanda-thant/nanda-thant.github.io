入門12 リトライは何回できる？

Basics 12 · How many retries?

2026-11-08 · やさしい 入門ループ

問題

API の呼び出しが失敗したら、少し待ってからリトライ（再試行）します。待ち時間は 1 回目が 1 秒で、そのあと 2 秒、4 秒、8 秒…と毎回 2 倍になります。

待ち時間の合計が T 秒を超えない範囲で、最大何回リトライできるか出力してください。

問題 (en)

When an API call fails, you wait a little and then retry. The first wait is 1 second, then 2 seconds, 4 seconds, 8 seconds … doubling each time.

Print the largest number of retries you can make while the total waiting time stays at T seconds or less.

問題 (my)

API ခေါ်ဆိုမှု မအောင်မြင်လျှင် ခဏစောင့်ပြီး retry (ထပ်ကြိုးစား) လုပ်သည်။ စောင့်ချိန်သည် ပထမအကြိမ် 1 စက္ကန့်၊ ထို့နောက် 2 စက္ကန့်၊ 4 စက္ကန့်၊ 8 စက္ကန့် … ဟု အကြိမ်တိုင်း နှစ်ဆ တိုးသည်။

စောင့်ချိန် စုစုပေါင်း T စက္ကန့် မကျော်သရွေ့ retry အများဆုံး မည်မျှ လုပ်နိုင်သည်ကို ထုတ်ပြပါ။

制約

  • 0 ≤ T ≤ 10⁹
  • T は整数

入力

T

出力

リトライの最大回数を出力してください。

入力例 1

10

出力例 1

3

1 + 2 + 4 = 7 秒で 3 回です。4 回目まで待つと 7 + 8 = 15 秒になり、10 秒を超えます。

入力例 2

0

出力例 2

0

入力例 3

1000000000

出力例 3

29

ヒント

何回繰り返すか最初にはわからないので、for ではなく while が向いています。「次の待ち時間を足しても T 以下なら、足して回数を 1 増やす」を繰り返しましょう。

ヒント (en)

You do not know in advance how many times to repeat, so while fits better than for. Repeat: "if adding the next wait still stays within T, add it and count one more retry".

ヒント (my)

ဘယ်နှစ်ကြိမ် ပတ်ရမလဲ ကြိုမသိသဖြင့် for ထက် while က ပိုသင့်တော်သည်။ «နောက်ထပ် စောင့်ချိန်ကို ပေါင်းလည်း T ထက် မကျော်လျှင် ပေါင်းပြီး အကြိမ်ရေ ၁ တိုး» ကို ထပ်ခါထပ်ခါ လုပ်ပါ။

解説

long total = 0, wait = 1;
int count = 0;
while (total + wait <= t) {
    total += wait;
    wait *= 2;
    count++;
}

while (条件) は条件が true の間ずっと繰り返します。条件がいつか必ず false になることを確かめましょう。ならないと無限ループです。ここでは wait が毎回 2 倍になるので、すぐに T を超えます。

T が大きいと total + wait が int の範囲に近づくので、long にしておくと安心です。

この「待ち時間を 2 倍ずつ増やす」方法はエクスポネンシャルバックオフと呼ばれ、実際の API クライアントでもよく使われます。

解説 (en)

while (condition) repeats as long as the condition is true. Make sure it eventually becomes false, or you get an infinite loop. Here wait doubles each time, so it passes T quickly.

For large T, total + wait gets close to the int limit, so long is the safe choice.

Doubling the wait is called exponential backoff, and real API clients use it.

解説 (my)

while (condition) သည် condition true ဖြစ်နေသရွေ့ ထပ်ခါထပ်ခါ လုပ်သည်။ တစ်ချိန်ချိန်တွင် false ဖြစ်မည်ကို သေချာပါစေ။ မဟုတ်လျှင် infinite loop ဖြစ်ပါမည်။ ဤနေရာတွင် wait သည် အကြိမ်တိုင်း နှစ်ဆ ဖြစ်သဖြင့် T ကို မကြာမီ ကျော်သွားသည်။

စောင့်ချိန်ကို နှစ်ဆစီ တိုးသည့်နည်းကို exponential backoff ဟုခေါ်ပြီး လက်တွေ့ API client များတွင် အသုံးများသည်။

T ကြီးမားသောအခါ total + wait သည် int ကန့်သတ်ချက်ကို ကျော်နိုင်သဖြင့် long သုံးခြင်းက ပိုလုံခြုံသည်။

解答 (Java)

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        long t = sc.nextLong();
        long total = 0;
        long wait = 1;
        int count = 0;
        while (total + wait <= t) {
            total += wait;
            wait *= 2;
            count++;
        }
        System.out.println(count);
    }
}
